# Қазақ батырлары туралы веб-жоба

> **Зертханалық жұмыстар:** № 6–10  
> **Жоба:** Мадиярдың «Желаяқ» және Нұрисламның «Алпамыс батыр» сайттары  
> **Қолданылған құралдар:** HTML, CSS, JavaScript, Git және GitHub

## Жобаның мақсаты

Қатысушылар дайындаған жеке веб-беттерді ортақ жобаға біріктіруді және GitHub арқылы топпен жұмыс істеуді үйрендік. Жұмыс барысында Git тармақтарын, Pull Request, Issues, Projects және GitHub Actions құралдарын қарастырдық.

## Сайттар туралы

Жобада екі жеке сайт бар:

| Қатысушы | Батыр | Сайттың мазмұны | Файл |
|---|---|---|---|
| Мадияр | Желаяқ | Қазақ ертегісіндегі жүйрік батыр, оның қасиеттері мен достары | `Madik-favorite-hero.html` |
| Нұрислам | Алпамыс батыр | Батырдың ерлігі, жыр желісі және тәрбиелік маңызы | `Tursyntay-favorite-hero.html` |

Екі сайтты байланыстыру үшін `index.html` басты бетін жасадық. Ондағы батырмалар жеке HTML беттеріне апарады:

```html
<a href="./Madik-favorite-hero.html">Мадияр — Желаяқ</a>
<a href="./Tursyntay-favorite-hero.html">Нұрислам — Алпамыс батыр</a>
```

Файл атауы мен `href` ішіндегі атау дәл бірдей болуы керек. Басты бет, екі сайт және қажет болса аудио файл бір жоба папкасында орналасады.

## Сайттардың мүмкіндіктері

**Желаяқ сайтында:**

- қазақ даласы, күн, тау және киіз үй бейнеленген;
- Желаяқ, Саққұлақ, Көлтаусар және Таусоғар туралы карточкалар бар;
- карточканы басқанда кейіпкердің сипаттамасы ашылады;
- бет бөлімдері айналдыру кезінде анимациямен көрінеді;
- `kui.mp3` файлын қосатын **«Күй»** батырмасы бар.

**Алпамыс батыр сайтында:**

- батыр туралы қысқаша мәлімет берілген;
- жыр оқиғалары кезеңдерге бөлінген;
- батырдың қасиеттері мен жырдың тәрбиелік маңызы көрсетілген;
- бет бөлімдеріне мәзірден өтуге болады.

## 6-зертханалық жұмыс: GitHub-та командалық жұмыс

Бұл жұмыста ортақ қашықтағы репозиториймен жұмыс істеу тәртібін қарастырдық. Қатысушы өз жұмысын жеке тармақта әзірлеп, GitHub-қа жіберіп, Pull Request ашты. Pull Request негізгі тармаққа біріктірілмес бұрын өзгерістерді қарап шығуға мүмкіндік береді.

Қақтығыс пайда болған жағдайда негізгі репозиторийдегі соңғы өзгерістерді алып, оларды жұмыс тармағымен біріктіруге болады. Қақтығысқан жолдарды түзетіп, өзгерісті қайта жіберу тәртібін үйрендік.

## 7-зертханалық жұмыс: Беттерді біріктіру

Бұл жұмыстың негізгі мақсаты — қатысушылардың беттеріне сілтемелер беретін ортақ `index.html` файлын жасау. Басты беттегі бірінші сілтеме Мадиярдың Желаяқ сайтына, ал екінші сілтеме Нұрисламның Алпамыс батыр сайтына бағыттайды.

Жоба файлдарының мысал құрылымы:

```text
жоба/
├── index.html
├── Madik-favorite-hero.html
└── Tursyntay-favorite-hero.html
```

Егер сайтқа аудио қосылса, аудио файл да өз HTML бетімен бір папкада сақталады:

```text
жоба/
├── Madik-favorite-hero.html
└── kui.mp3
```

## 8-зертханалық жұмыс: Тапсырмаларды жоспарлау және автоматтандыру

GitHub Issues тапсырмаларды жазуға, орындаушыға бекітуге және белгілермен бөлуге көмектеседі. Мысалы, басты бетке сілтеме қосу немесе HTML файлының атауын тексеру үшін жеке Issue ашуға болады.

GitHub Projects тақтасында тапсырмаларды келесі кезеңдерге орналастыруға болады:

| Баған | Мағынасы |
|---|---|
| To Do | Орындауды күтіп тұрған тапсырмалар |
| In Progress | Қазір орындалып жатқан тапсырмалар |
| Review | Тексеруге жіберілген тапсырмалар |
| Done | Аяқталған тапсырмалар |

GitHub Actions workflow файлы `.github/workflows/` папкасында сақталады. Push немесе Pull Request болғанда workflow автоматты түрде іске қосылуы мүмкін.

## 9-зертханалық жұмыс: CI/CD

CI — код репозиторийге жіберілген сайын жобаны автоматты тексеру. CD — тексерілген жобаны дайын ортаға жеткізу немесе жариялау. Осы әрекеттерді ретімен орындайтын қадамдар жиынтығы **pipeline** деп аталады.

Жұмыста GitHub Actions файлында келесі кезеңдерді ұйымдастыру үлгісін қарастырдық:

1. Репозиторий кодын workflow ортасына жүктеу.
2. Жобаның build қадамын орындау.
3. Тест немесе тексеру қадамын іске қосу.
4. Қажет болса, deploy қадамын орындау.

Ескерту: workflow ішінде `echo` командасы ғана болса, ол нақты сайтты жарияламайды. Ол қадамның орындалғанын көрсететін үлгі ретінде қолданылады. Нақты орналастыру үшін hosting қызметіне арналған deploy баптауы қажет.

## 10-зертханалық жұмыс: Нұсқалар мен релиз

Жобаның дайын нұсқасын белгілеу үшін Git tag қолданылады. Мысалы, `v1.0.0` алғашқы тұрақты нұсқаны білдіреді. GitHub Release осы тегке байланыстырылып, шығарылымдағы өзгерістерді сипаттайды.

`CHANGELOG.md` файлының үлгісі:

```markdown
## v1.0.0

- Қазақ батырлары жобасының басты беті қосылды
- Желаяқ пен Алпамыс сайттарына сілтемелер енгізілді
- Желаяқ бетіне «Күй» батырмасы қосылды
- GitHub Actions workflow файлдары дайындалды
```

Тег құру және GitHub-қа жіберу мысалы:

```bash
git tag v1.0.0
git push origin v1.0.0
```

## Жұмыста қолданылған Git командалары

| Команда | Мақсаты |
|---|---|
| `git status` | Жоба күйі мен өзгерістерді көру |
| `git branch` | Тармақтар тізімін көру |
| `git checkout -b feature-update` | Жаңа жұмыс тармағын құру |
| `git add .` | Өзгерістерді commit-ке дайындау |
| `git commit -m "Сипаттама"` | Өзгерістерді сақтау |
| `git push origin feature-update` | Тармақты GitHub-қа жіберу |
| `git pull upstream master` | Негізгі репозиторийдегі өзгерістерді алу |
| `git tag v1.0.0` | Жоба нұсқасына тег қою |

## Қорытынды

6–10-зертханалық жұмыстарда GitHub-та жобаны топпен басқару, жеке веб-беттерді ортақ басты бетке біріктіру және өзгерістерді Pull Request арқылы тексеру тәсілдерін қарастырдық. Сонымен қатар Issues пен Projects арқылы тапсырмаларды жоспарлау, GitHub Actions workflow құру, CI/CD кезеңдері және Git tag пен Release арқылы нұсқаларды белгілеу жолдарымен таныстық.

Нәтижесінде Мадиярдың Желаяқ сайты мен Нұрисламның Алпамыс батыр сайты бір жобаның құрамына біріктіріліп, оларды `index.html` бетінен ашуға мүмкіндік жасалды.
